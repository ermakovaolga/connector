# Сonnector Policy: подружить лабовские VPN на одном Mac

Обычно FortiClient ITMO и VPN лаборатории мешают друг другу. VPN Policy позволяет держать их включёнными одновременно.

Ресурсы лаборатории ITMO (`*.dgx`) идут через FortiClient.
Весь остальной трафик идёт как обычно: напрямую или через ваш второй VPN.

- **Ваш FortiClient остаётся вашим.** Каждый подключается к ITMO сам, через свой SSO.
  Общего туннеля или общего аккаунта нет.
- **Управление:** кружок в строке меню, кнопка «Включить / Выключить».
- **Платформа:** macOS (Apple Silicon и Intel). Версия для Windows пока в разработке, см. [ниже](#windows).

## Установка

Нужно:
- права администратора на Mac;
- FortiClient с настроенным подключением ITMO.

Шаги:

1. Скачайте `vpnpoc-macos.zip` из раздела **Releases** этого репозитория и распакуйте.
2. В Терминале выполните:
   ```bash
   cd ~/Downloads/vpnpoc-macos
   ./install.sh          # спросит пароль администратора, один раз
   ```
3. Справа вверху в строке меню появится кружок.

Агент запускается сам после каждой перезагрузки. Пароль больше не понадобится.

## Использование

1. Подключите FortiClient ITMO, как обычно.
2. Проверьте, что кружок в строке меню зелёный.
3. Открывайте `*.dgx`. Для быстрой проверки есть пункт меню «Открыть d.dgx:18888».

| Кружок | Что значит |
|---|---|
| 🟢 зелёный | включено: `*.dgx` идут через FortiClient |
| ⚪ серый | выключено: всё работает так, будто агента нет |
| 🟠 оранжевый | проблема: служба не отвечает или не удалось включить (агент повторяет попытку сам) |

Пункты меню:

- **Включить / Выключить**: главная кнопка. Выбранное состояние сохраняется после перезагрузки.
- **`itmo: ✓ utunN`**: FortiClient подключён. **`itmo: не подключён`**: подключите FortiClient.
- **Открыть лог**: пригодится, если что-то не работает.
- **Скрыть значок**: убирает только значок, агент остаётся в том же состоянии. Значок вернётся после
  перезагрузки или если открыть «VPN Policy» из папки «Программы».

## Если не работает

| Симптом | Что делать |
|---|---|
| В меню `itmo: не подключён` | Подключите FortiClient ITMO |
| Кружок оранжевый | Меню → «Открыть лог», посмотрите последние строки |
| `d.dgx` не открывается в Chrome, а в Safari открывается | Выключите в Chrome «Использовать безопасный DNS»: Настройки → Конфиденциальность и безопасность → Безопасность |
| В браузере `404 page not found` по адресу `127.0.0.1:47391` | Это служебный адрес агента, не страница. Управление находится в строке меню |
| Нужно, чтобы агента не было совсем | Удалите его, см. ниже |

Если не помогло, создайте issue и приложите:
- вывод `tail -50 /var/log/vpnpoc.log`;
- вывод `/usr/local/vpnpoc/vpnpoc probe -c /usr/local/vpnpoc/config.yaml`.

## Удаление

```bash
sudo /usr/local/vpnpoc/uninstall.sh
```

Команда удаляет службу, значок, настройки DNS и маршруты агента. Система возвращается в исходное состояние.

## Как это работает

Агент не трогает маршруты FortiClient и второго VPN. Он делает три вещи:

1. **Перехватывает DNS только для `*.dgx`.** Имена спрашивает у DNS ITMO через туннель FortiClient.
2. **Соединения к этим адресам открывает сам,** привязывая их к интерфейсу FortiClient.
   Поэтому неважно, какой VPN сейчас владеет маршрутом «по умолчанию».
3. **Закрепляет маршрут до шлюза ITMO за обычным интернетом.** Иначе full-tunnel VPN
   заворачивает соединение FortiClient в себя, и туннель ITMO рвётся.

Какие домены и адреса идут через ITMO, задаётся в [config.yaml](config.yaml).
Подробности, найденные особенности macOS и история экспериментов собраны в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md).

## Для разработчиков

Нужен Go 1.26+ и Xcode Command Line Tools (для значка в меню нужен cgo).

```bash
./packaging/build.sh                  # → dist/vpnpoc-macos.zip (универсальный: arm64 + x86_64)

go build -o vpnpoc .                  # только агент
./vpnpoc probe                        # проверка без root: интерфейсы, DNS, соединения через ITMO
sudo ./vpnpoc run                     # агент в терминале, без службы (Ctrl+C: остановить и убрать за собой)
```

Устройство кода:

| Файл | Что внутри |
|---|---|
| `main.go` | команды `probe`, `run`, `daemon` |
| `agent.go` | включение и выключение, отслеживание смены сети |
| `control.go` | локальный API для значка (`127.0.0.1:47391`) |
| `policy.go`, `dns.go`, `handler.go` | правила, DNS с fake-IP, пересылка TCP/UDP |
| `outbound.go` | сокеты, привязанные к интерфейсу VPN |
| `sys_darwin.go`, `sys_windows.go` | маршруты и DNS конкретной ОС |
| `tray/` | приложение для строки меню |
| `packaging/` | сборка, `install.sh`, `uninstall.sh` |

Выпуск новой версии:
1. Соберите `./packaging/build.sh`.
2. Приложите `dist/vpnpoc-macos.zip` к новому Release. Сам zip в репозиторий не коммитится.

Если поменялся `config.yaml`, коллегам достаточно переустановить: `install.sh` ставит новый конфиг,
а прежний сохраняет в `/usr/local/vpnpoc/config.yaml.bak`.

### Добавить ещё домен через ITMO

В `config.yaml`:

```yaml
rules:
  - domain_suffix: [dgx, другой.домен]
    dns: 10.32.1.3
    outbound: itmo
```

Проверяйте только домены, которые действительно открываются через ITMO. Например, `tatneft.guru`
через ITMO не проходит: шлюз ITMO не пускает на его адрес. Проверить новый домен можно командой `./vpnpoc probe домен:443`.

## Windows

Код общий, версия для Windows собирается (`GOOS=windows`), но на реальной машине ещё не проверялась.
Чего не хватает:
- `wintun.dll` в пакете;
- маршрута до шлюза ITMO мимо второго VPN (`bypass`);
- отслеживания смены сети;
- установщика со службой.

Если у вас Windows и оба VPN, напишите: нужен первый тестировщик.

## Статус

Это proof of concept. На macOS проверено: доступ к `d.dgx` через FortiClient при
одновременно включённом full-tunnel VPN, стабильность туннеля ITMO, включение и выключение из меню.
Работает только IPv4.
